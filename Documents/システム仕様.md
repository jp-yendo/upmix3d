# システム仕様

## 構成

VLCが入力形式とレートを変換する。PCMはWG4順の最大9位置で受け取り、出力スレッドがリングから取り出してDSPを実行する。出力スレッドはCOMの初期化、ストリームの生成・制御・破棄を所有する。キュー満杯時は書き込みを待ち、停止・エラーでは待機を解除する。

| ファイル | 責務 |
|---|---|
| `src/core.cpp` | 正規化、構成判定と構成名、STFT、生成・混ぜ込み・LFE、レベル保護の適用 |
| `src/limiter.cpp` | 先読みピークリミッター（サンプルピーク／4倍補間トゥルーピーク、保持による正規化） |
| `src/profiles.cpp` | 14入力構成とプリセット値の合成 |
| `src/transport.cpp` | 圧縮形式の許可、キャリアと変換レート、バイト保持リング |
| `src/boundary.cpp` | 余弦形状の境界ゲイン |
| `src/speaker_test.cpp` | スピーカーテストの信号と位置名 |
| `src/windows_audio.cpp` | デバイス・形式交渉、空間オブジェクト、WASAPI、クロック、音量 |
| `src/vlc_module.cpp` | VLC登録・設定・コールバック、保存、イベント処理、復旧、遅延報告 |

信号処理部（`core.cpp`、`limiter.cpp`、`profiles.cpp`、`transport.cpp`、`boundary.cpp`、`speaker_test.cpp`）はVLCとWindowsの出力APIに依存せず、`upmix3d_core`として単体でテストする。

## 入出力構成

入力の9位置はFL、FR、FC、LFE、SL、SR、BL、BR、BCで、それぞれ同名のAudioObjectTypeに割り当てる。側方を持たず後方だけを持つ入力（4.0、4.1、5.0、5.1）は、後方を側方として扱う。

ダウンミックスOFFでは入力と設定の和集合、ONでは設定した構成を出力する。機器の制限で表現できない位置は、ダウンミックスOFFでもログを出して近い位置へ混ぜ込む。

ハイトありの構成は、ハイトを含む総チャンネル数をN.1の形で併記する（例：5.1.2 (7.1)、7.1.4 (11.1)）。ログの構成名は、出力構成の一覧、入力構成の一覧、出力構成と後方センターの組（例：`7.1.4 (11.1) + BC`）、位置名の列挙の順に照合する。

## 信号処理

処理順は、アップミックス（水平方向）、ハイト生成、ダウンミックス、レベル保護。抽出はダウンミックス前の入力から行う。

### センター

- **ステレオ:** マトリクスは0.5(L+R)、STFTは帯域ごとの左右の類似度で重み付けた中央成分を共通成分cとする。抽出量をe、センター幅をa（設定値/7）とすると、センターは√2・e・c・√(1−a)、左右からはe・c・(1−√a)を引く。センター幅0では抽出分をすべてセンターへ移し、7では元の左右に戻す。いずれも共通成分の電力を保つ。
- **モノラル:** センターに√(1−a)、左右に√(a/2)ずつ配分する。センター幅0ではセンターだけから出る。

### サラウンド

- アンビエンス（マトリクスは左右の差、STFTは共通成分を除いた残り）に、入力の側方・後方を加えて生成する。
- 側方と後方のレベルには、それぞれ「ディメンション×2dB」を加える。正の値で後方寄りになる。
- 遅延と無相関化をかける。無相関化はオールパスとの混合で、100%で半分、200%ですべてをオールパスの出力にする。

### 台詞保護

- STFTでは、アンビエンスの200〜4000Hzを0.15倍にする。時間領域でも、同じ帯域を0.85倍分差し引く。
- 1kHzのアンビエンスに対する減衰量は、マトリクスで約13dB、STFTで約29dB。
- 声と同じ帯域の楽器は区別できないため、完全な除去ではない。

### ハイト

- アンビエンスに1次の高域通過をかけて生成する。上前方と上後方は、位置ごとに異なるオールパスを通した無相関の信号にする。
- ハイト4本の構成では、前後バランスbに対して上前方に√((1−b)/2)、上後方に√((1+b)/2)を掛ける。
- STFTは元の音と生成音の分析遅延（窓サイズ分）を合わせる。

### ダウンミックス・LFE

- 混ぜ込み先は次のとおり。
  - センター：前方左右
  - 後方センター：後方左右（ない構成では側方左右、それもなければ前方左右）
  - 後方：側方（なければ前方）
  - 側方：後方（なければ前方）
  - 上前方：前方
  - 上後方：後方（なければ側方、それもなければ前方）
- LFEは生成せず、入力にある場合だけレベルを調整して出力する。LFEのない構成では、設定に従って捨てるか前方左右へ混ぜ込む。

### レベル保護

全体ゲインとLFEレベルを掛けた後に適用する。

| 方式 | 動作 |
|---|---|
| 固定減衰 | -6dBにして±1で制限する。入出力の構成が一致するPCMには適用しない（処理による増加がないため） |
| 正規化 | 先読みピークリミッターで、下げたゲインを開始・シークまで戻さない |
| リミッター | 先読みピークリミッターで、ピークの後に時定数100msで1へ戻す |

先読みピークリミッターの仕組みは次のとおり。

- 全位置を連動して扱う。トゥルーピーク測定時は、24タップの窓付きsincで隣接サンプル間の3点を補間し（4倍補間、ITU-R BS.1770と同じ測り方）、両端のサンプルと合わせて区間のピークとする。サンプルを含む前後2区間の小さい方の必要ゲインを、そのサンプルの必要ゲインにする。
- 必要ゲイン（しきい値/ピーク）に1.5msの区間最小値をとり、同じ長さの移動平均をかける。ピークのサンプルが出るときにはゲインが必要値以下に下がっており、ゲインが段差状に変わることはない。
- 遅延は「攻撃区間−1」サンプルで、トゥルーピーク測定時は補間の分の12サンプルが加わる。48kHzではそれぞれ71、83サンプル。
- しきい値を超えない信号は、遅延を除いてサンプル値を変えない。リミッターの回復は、残差0.0001未満で1に戻して透過状態に戻す。
- 制御後の真のピークは、4倍補間で測ってしきい値+0.02dB以内。16倍補間で測ると、ナイキスト付近まで成分を持つ広帯域ノイズでしきい値+0.2dB以内になる（4倍補間で測ることによる過小評価）。
- 番組ラウドネスの測定・正規化（EBU R 128）は対象外。

### PCMパススルー

入出力の構成が一致し、全体ゲインとLFEレベルが0dBのときは、アップミックスを行わず各位置へそのまま割り当てる。固定減衰はかけない。正規化とリミッターは、しきい値を超えるピークがない限り値を変えない。最初の開始時には境界フェードをかけず、シークと一時停止の前後だけフェードする。

## 出力経路と復旧

- ハイトを含む構成は空間オーディオに固定する。ハイトなしでは、空間オーディオ・共有WASAPI・排他WASAPIから選ぶ。
- 空間オーディオでは、ネイティブ静的マスクに含まれる位置を静的オブジェクトにし、含まれない位置を動的オブジェクトにする。動的の上限はGetMaxDynamicObjectCountに従う。
- `.2`の真上配置では、上前方の2本を動的オブジェクトとして、聴取位置の真上（高さ1m、左右に0.5mずつ）に置く。後方センターの動的オブジェクトは真後ろに置く。
- オブジェクトの形式は、対応形式の一覧のうち最初のモノラル32bit floatを使い、VLCには同じレートのFL32を要求する。
- 動的オブジェクトを確保できない位置は、使える静的位置へ混ぜ込んでログに出す。
- 空間オーディオを使えない場合（動的上限0、アクティベーション失敗等）は共有WASAPIへ切り替え、7.1以下でデバイスが受け付ける構成に制限する。排他PCMの取得に失敗した場合も共有WASAPIへ切り替える。
- 処理要求イベントは100msで待機を区切る。空間オーディオで2回まではReset後に再開し、続けてタイムアウトした場合は失敗として扱う。
- 実行中の失敗では、VLCに出力の再初期化を要求する。最初の失敗は設定した経路で再初期化し、続けて失敗した場合は共有WASAPIで再初期化する。失敗回数は5秒間正常に出力すると0に戻る。
- 失敗から5秒以上後の開始は新しいストリームとみなし、設定した経路から試す。デバイスの変更・選択でも設定した経路に戻す。
- 出力デバイスの変更・形式変更の通知を受けると、VLCに出力の再初期化を要求する。
- 設定どおりに出力できない次の場合は、原因と対処を`vlc_dialog_display_error`で表示する。同じ文面はVLCのセッション中に1回だけ表示し、ログにも出す。失敗からの復旧で共有WASAPIにした場合は表示しない。
  - 空間オーディオを使えず共有WASAPIにした（空間サウンドの有効化を案内）
  - 排他PCMを使えず共有WASAPIにした（他のアプリと排他モードの許可を案内）
  - 機器が要求した構成の一部の位置を出せず、混ぜ込んだ（後方センターを設定で混ぜ込む場合を除く）
  - ビットストリーム出力を開けず、VLCのデコードに戻した（ポリシーで拒否した場合を除く）

## ビットストリーム

VLCの変換フィルターがIEC 61937へ格納し、モジュールはバイト列のまま排他WASAPIへ渡す。DSP・並べ替え・音量・フェードは適用しない。対象外の形式や形式交渉の失敗は開始時に拒否し、VLCのPCMデコードに戻す。サブタイプはVLC 3.0系の標準WASAPI出力と同じにする。

| 形式 | Windowsキャリア | VLC変換用レート |
|---|---|---|
| AC-3 / DTSコア | 通常48kHz・2ch・16bit（44.1kHzのDTSはPCMサブタイプ） | 入力レート |
| E-AC-3 | 入力レートの4倍・2ch・16bit | キャリアレート |
| DTS-HD | 48kHz系は192kHz、44.1kHz系は176.4kHz・8ch・16bit | キャリアの4倍に相当する4バイト単位の周期 |
| TrueHD / MLP | 48kHz系は192kHz、44.1kHz系は176.4kHz・8ch・16bit | キャリアレート |

- 時間は、キューのバイト数と実キャリアの毎秒バイト数から求める。DTS-HDの変換レートはWindowsのクロックに使わない。
- 対応するレート系統を判定できない高ビットレート入力はPCMへ戻す。
- 既成のビッグエンディアンIEC入力は、16bit単位でWindowsの順に直す。
- 「AC-3とDTSのみ」の設定では、DTS-HD入力をDTSコアで送る。DTS-HDの伝送を開けない場合もDTSコアで送る。

## 設定・同期・再生制御

- **プリセット:** 構成別指定、モノ／ステレオまたは多チャンネル指定、全体指定の順で決める。前回適用した値を基準として個別の変更を検出し、カスタムへ移行する。適用値と基準はVLCの設定APIに書き込み、`upmix3d-save-settings`が有効なら開始時に設定ファイルへ保存する。
- **遅延:** 入力キュー、DSP内の未排出量（分析窓と先読み）、IAudioClockとQPCによる未再生量、経路別の補正を合計する。64bitカウンターを使い、経過時間を繰り返し足し合わせることはしない。
- **再生制御:** 一時停止では入力位置とDSPを保持し、短いフェード後に停止する。シークではキューとDSPを破棄する。待機ありのflushでは処理末尾を流し、再生し終えるまで待つ。
- **音量:** IAudioStreamVolumeで反映する。サービスがない場合は、オブジェクトの音量または出力サンプルに掛ける。100%を超える分は入力に掛ける。
- **遅延モード:** 低遅延はマトリクス処理と10msの出力バッファを使う。標準は設定した方式・窓・ホップ（既定はSTFT、窓2048・ホップ512）と20msの出力バッファを使う。高品質は窓4096・ホップ1024と20msの出力バッファを使う。
- **反映時期:** 音量・ミュート・デバイス選択は再生中に反映する。DSP・構成・経路の設定はストリーム開始時に読み込む。

## スピーカーテスト

VLC 3.0の設定画面にはボタンを置けないため、`upmix3d-speaker-test`（既定OFF）で次回の再生開始時に1回だけ実行する。

- PCMの開始時に設定を読み、ONなら直ちにOFFにして設定ファイルへ保存する。ビットストリームの開始では読まず、設定はONのまま残す。
- 実際に開いた出力構成の全位置を、`channels`の順に1位置ずつ鳴らす。各位置は1秒の音と0.5秒の無音で、両端に50msのフェードをかける。通常位置はピンクノイズ、LFEは60Hzの正弦波で、どちらも約-30dBFS RMS。
- テスト中は、DSPの出力をテスト信号に置き換える。入力の取り込みとDSPの処理は続けるため、遅延の報告と同期は変わらない。ミュートとソフトウェア音量はテスト信号にも掛ける。
- 出力スレッドが、鳴らしている位置名と番号をVLCの進行状況ダイアログ（`vlc_dialog_display_progress`）に表示し、ログにも出す。ダイアログの［Stop］で中止する。ダイアログを表示できない環境ではログだけを出す。

## 技術上の前提

| 対象 | 採用する仕様 |
|---|---|
| VLC | 公式3.0.24 x64配布物の`sdk`と同梱の`libvlccore.lib`を使う。エントリーポイントは`vlc_entry__3_0_0f`。同じ公開名だけでは全更新版の互換性を保証しないため、配布対象のVLCで読み込みを確認する |
| コンパイラー | Visual Studio 2026、v145、C++20、MSVCランタイムは静的リンク |
| 文字列の所有権 | VLCが確保した文字列は、libvlccoreがインポートする`free`で解放する。MSVC側の`free`には渡さない |
| VLCヘッダー | `ssize_t`、`restrict`、`poll`をVLCヘッダーより前に定義する。MSVCの標準ヘッダーは`restrict`の定義より先に読む |
| 形式交渉 | IsFormatSupportedで照会し、共有WASAPIでは受け付けられない構成をデバイスの構成に合わせて混ぜ込む |
| 参照 | [Spatial Sound](https://learn.microsoft.com/en-us/windows/win32/coreaudio/spatial-sound)、[IEC 61937の形式](https://learn.microsoft.com/en-us/windows/win32/coreaudio/representing-formats-for-iec-61937-transmissions)、[VLCのIEC格納](https://github.com/videolan/vlc/blob/3.0.x/modules/audio_filter/converter/tospdif.c)、[ITU-R BS.1770](https://www.itu.int/rec/R-REC-BS.1770) |

オブジェクト数とエンコード形式は、機器とWindowsの設定に従う。プリセット値は公開されている一般的な値を初期値としており、受信機と部屋に応じて試聴で調整する。

## ログ

開始時に、入力構成と適用したプリセット、PCMの入力構成・出力構成・経路・レート・DSP遅延（またはビットストリームの形式・キャリア）を出力する。経路の自動切り替え、混ぜ込み、イベントのタイムアウト、失敗と再初期化の方法も記録する。

## 検証

| 実行 | 内容 |
|---|---|
| `scripts/verify.ps1` | ビルド、コアテスト、10秒分のDSP性能測定 |
| `scripts/verify.ps1 -DeviceTests` | ポータブルVLCを使う無音の結合テスト24件（3経路、真上配置、後方センター、プリセット、デバイス選択、再生制御、遅延モード、スピーカーテスト、全ビットストリーム形式、PCMへのデコード） |
| `scripts/verify.ps1 -LongDsp` | 2時間分のステレオから7.1.4へのSTFT処理。1秒ごとに強い入力と通常入力を交互に与え、非有限値とクリップを検出する |

- コアテストでは次を検証する。
  - 全入力構成×全出力構成×ダウンミックスON/OFF
  - 構成名
  - センターの電力保存
  - STFTの再構成
  - 全保護方式でのPCMパススルーのサンプル値一致
  - しきい値未満の正弦波でリミッターが動作しないこと
  - 補間ピークの上限
  - ゲインが連続的に変わることと、1への回復
  - 正規化での保持
  - スピーカーテストの順序、1位置ずつの出力、無音区間、レベル、終了と中止
  - リング、時間単位
- 結合テストは、プレーヤーをミュートして実行し（スピーカーテストも鳴らない）、設定を`build/integration/test.vlcrc`に限定し、Windowsの既定デバイスやインストール済みのVLCを変更しない。判定はログと再生の完了で行い、音の内容は検証しない。
- `tests/fixtures/`は48kHz・5.1・約3秒の無音の圧縮音声。AC-3とE-AC-3は448kbps、DTSコアは768kbps、TrueHDはロスレス。Atmosメタデータは含まない。DTS-HDの検証では、DTSコアを高ビットレート形式で格納する。
- 生成物とSDKはGitの管理対象外。

次は実機でしか確認できない受け入れ項目である。

- AVアンプのAtmos表示と、ハイトを含む各スピーカーの出音・定位。
- VLCの画面でのスピーカーテストのダイアログ表示と［Stop］による中止、出力できない場合のメッセージ表示。
- Atmosメタデータを含む実際のTrueHD・E-AC-3コンテンツの受信。
- 2時間の動画を実時間で再生したときの映像同期、受信機の遅延と手動補正。
- HDMIの抜き差し、空間形式の変更、オブジェクト不足時の継続性と聴感。
- Windows 10 1703での互換性、機種ごとのクリック音・台詞保護・音質。
